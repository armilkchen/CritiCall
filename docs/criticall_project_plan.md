# CritiCall / 911 Dispatcher Skills Prep 项目方案

## 1. 项目背景

### 1.1 项目起点

本项目来自对"微垂直职业考试知识付费"模式的调研。

目标不是进入 SAT、雅思、CompTIA 等高度拥挤的大型考试市场，而是寻找：

-   搜索流量不必很大，但必须长期存在；
-   用户有明确考试日期和通过目标；
-   考试结果与求职、入职或职业机会相关；
-   用户有真实付费意愿；
-   已有竞争者可以验证市场，但尚未严重饱和；
-   不依赖很强的行业专业知识；
-   可以主要依靠官方公开资料、公开互联网资料、AI 和程序化内容生产；
-   产品不能只是容易被 AI Summary 替代的静态文章或 PDF。

经过对多个美国、加拿大、英国、爱尔兰及欧洲职业考试方向的横向扫描，CritiCall
/ 911 Dispatcher Hiring Test 是目前较符合条件的候选。

### 1.2 为什么选择 CritiCall

CritiCall 常用于 911 Dispatcher / Public Safety Dispatcher / Call Taker
等岗位的招聘测试。

它与传统职业资格考试最大的不同是：

**它主要测试能力，而不是专业知识。**

常见能力包括：

-   Data Entry
-   Audio Data Entry
-   Typing
-   Short-Term Memory
-   Decision Making
-   Multitasking
-   Cross Referencing
-   Map Reading / Geographic Orientation
-   Call Summarization
-   Reading Comprehension
-   Spelling / Proofreading
-   Basic Numerical Ability

不同招聘机构可以选择不同测试模块，因此不存在完全统一的全国试卷。

这意味着本项目不能声称复刻真实 CritiCall，也不能提供所谓"真实考试题"。

产品定位应该是：

> **911 Dispatcher Skills Practice / CritiCall-style Test Preparation**

核心价值不是"告诉用户 CritiCall 考什么"，而是让用户真正练习这些能力。

## 2. 市场判断

### 2.1 用户痛点

目标用户通常处于非常明确的时间窗口：

> "我申请了 dispatcher，现在两周后要参加测试。"

他们的核心问题不是：

> "CritiCall 是什么？"

而是：

> "我到底准备好了吗？"

> "我的 typing 没问题，但 multitasking 会不会挂？"

> "哪里可以练 audio data entry？"

> "付费 practice test 到底值不值得？"

这种用户具有：

-   明确 Deadline；
-   求职驱动；
-   Pass / Fail 心态；
-   考试焦虑；
-   较高的即时购买意图。

### 2.2 已验证的商业市场

当前市场已有多个付费玩家，例如：

-   JobTestPrep
-   JobPrepCentral
-   9-1-1 Professor
-   其他 dispatcher / aptitude test prep 网站

现有产品价格大致覆盖约 \$20 到 \$60+
的区间，并存在长期用户评价和真实购买讨论。

因此本项目不需要重新证明：

> "用户会不会为 CritiCall preparation 付钱？"

答案已经得到市场验证。

我们的任务是判断：

> **能否用更聚焦、更现代、更强交互的产品，在这个已经存在的市场里获得一小部分份额。**

### 2.3 对竞争的态度

本项目不追求"完全没有竞争"。

相反：

**存在竞品通常意味着市场已经被验证。**

真正需要避免的是：

-   大量专业品牌；
-   大量成熟 SaaS；
-   极高 SEO 权重；
-   用户已经形成极强品牌认知；
-   产品严重同质化且价格被压到极低。

CritiCall 当前属于：

> **有成熟玩家，但尚未达到完全人满为患。**

因此适合进行 MVP 验证。

## 3. 核心产品定位

不要把网站定位为：

> "1000+ CritiCall Questions"

也不要主要卖：

> "Ultimate CritiCall PDF Guide"

推荐定位：

# Train for the pressure of a dispatcher hiring test.

核心概念：

> **用户单独做每项能力可能很好，但在中断、多任务和时间压力出现后，准确率会明显下降。**

因此我们的差异化不是题库数量，而是：

## Pressure Training

产品希望回答：

> **What happens to your accuracy under pressure?**

## 5. MVP 产品范围

第一版不要追求覆盖所有 CritiCall 模块。

### 必做模块

#### 1. Typing & Data Entry

测试：

-   打字速度；
-   准确率；
-   Name / Address / Phone / Plate 等结构化数据输入。

#### 2. Alphanumeric / VIN / Plate Practice

程序自动生成：

-   VIN-like strings
-   Plate numbers
-   Unit IDs
-   Phone numbers
-   Mixed alphanumeric sequences

无需传统人工题库。

#### 3. Audio Data Entry

AI/TTS 播放：

-   姓名
-   地址
-   电话
-   Vehicle
-   Plate
-   其他结构化信息

用户听后填写对应字段。

#### 4. Short-Term Memory

示例：

显示：

`K7F29Q`

数秒后隐藏。

要求 Recall。

后续可扩展：

-   Audio memory
-   Address memory
-   Vehicle information memory

#### 5. Decision Making

基于一个经过人工审核的简单规则体系生成 scenario。

例如：

-   Fire-related incident → Fire
-   Medical emergency → EMS
-   Crime / suspicious activity → Police

重点是测试快速分类和规则执行，不模拟真实 911 dispatch protocol。

#### 6. Multitasking / Interruption

这是 MVP 核心。

例如：

用户正在输入：

-   VIN
-   Address
-   Caller information

突然出现：

> Incoming Incident

用户需要：

1.  暂停当前任务；
2.  完成快速判断；
3.  回到原任务；
4.  保持准确率。

系统比较：

-   Baseline Accuracy
-   Pressure Accuracy
-   Pressure Drop

### V1.1 再增加

-   Map Reading
-   Cross Referencing
-   Call Summarization

### 后续再考虑

-   Reading Comprehension
-   Spelling
-   Proofreading
-   Numerical Ability
-   Probability / Information Frequency
-   Agency-specific training

## 6. 内容与"题库"策略

### 6.1 不建立传统庞大题库

本项目不应该人工制作 5,000 道固定题。

大量内容都可以程序生成。

例如：

#### Alphanumeric

``` text
7KX29B
1HGCM82633A004352
82QF7M
```

#### Address

``` text
1842 West Pine Street, Apt 4B
781 North Oak Avenue
2635 East Jefferson Road
```

#### Memory

随机生成字符串、号码、地址和姓名组合。

#### Cross Reference

动态生成大量高度相似的数据：

``` text
AJK274
AJK247
AJX274
AJM274
```

然后要求用户寻找指定目标。

因此营销语言可以从：

> 1,000+ Questions

变成：

> **Unlimited Adaptive Drills**

### 6.2 AI 负责什么

AI 适合：

-   Scenario 文案变体；
-   Caller script；
-   Call summarization 内容；
-   SEO 内容辅助；
-   Explanation；
-   不同难度的语言表达；
-   生成自然的无关信息和干扰信息。

### 6.3 AI 不负责什么

AI 不应该自由决定：

-   官方 passing score；
-   某 agency 的考试结构；
-   真实 CritiCall 内容；
-   关键训练规则的正确答案；
-   Police / Fire / EMS 等分类规则。

关键答案应该由：

> **人工审核的规则集 + 程序逻辑**

决定。

## 7. Audio 技术路线

Audio 是产品的重要组成部分，但不需要人工录制大量语音。

推荐流程：

``` text
Structured Data
      ↓
Script Generator
      ↓
TTS
      ↓
Audio Playback
      ↓
User Input
      ↓
Programmatic Scoring
```

例如系统首先生成：

``` text
Name: Jennifer Collins
Address: 1842 West Pine Street
Phone: 555-827-1946
Vehicle: Blue Honda Civic
Plate: 7KX29B
```

再生成语音脚本：

> Hi, my name is Jennifer Collins. I'm at 1842 West Pine Street. There's
> a blue Honda Civic outside...

通过 TTS 转换为语音。

用户听完填写：

-   Name
-   Address
-   Phone
-   Vehicle
-   Plate

因为系统本身保存结构化标准答案，因此评分不需要 LLM。

### Audio 难度

#### Easy

-   慢速；
-   信息顺序固定；
-   无干扰。

#### Normal

-   正常语速；
-   顺序随机；
-   少量无关信息。

#### Hard

加入：

-   信息纠正；
-   重复；
-   更快语速；
-   更长句子。

例如：

> It's 1842---sorry, 1846 West Pine Street.

#### Pressure

播放 Audio 的同时加入：

-   popup alert；
-   memory task；
-   decision task；
-   interruption。

### TTS 注意事项

数字、车牌、VIN 等不要完全依赖 TTS 自动解释。

程序应先转换为预期读法。

例如：

``` text
7KX29B
```

转换为：

``` text
Seven Kilo X-ray Two Nine Bravo
```

再交给 TTS。

后期可增加：

-   不同声音；
-   不同语速；
-   不同口音；
-   紧张/平静 caller；
-   background noise。

MVP 暂时不需要复杂背景噪音。

## 8. 技术架构建议

目标：

> **快速上线，而不是搭建复杂平台。**

### Frontend

推荐：

-   Next.js
-   React
-   TypeScript
-   Tailwind CSS

原因：

-   SEO 友好；
-   Landing Page 和 Web App 可以共用；
-   很适合 Timer / Keyboard / Audio / Interactive Drill；
-   后续 Programmatic SEO 容易扩展。

### Backend

可以直接使用：

-   Next.js API Routes / Server Actions

早期无需单独建设复杂后端。

### Database

推荐：

-   PostgreSQL
-   Supabase 或 Neon

核心数据：

-   User
-   Session
-   Drill Result
-   Assessment
-   Purchase
-   Training History
-   Scenario Template

### Authentication

可使用：

-   Clerk
-   Supabase Auth
-   Auth.js

免费 Assessment 尽量不要强制登录。

付款后再创建账户。

### Payment

推荐：

-   Stripe

MVP：

> 一次性付款 → 30 天访问权限

暂时不需要 Subscription。

### TTS

可根据成本和效果选择主流 TTS API。

MVP 核心要求：

-   英文自然；
-   latency 可接受；
-   数字/字母读音稳定；
-   支持预生成或缓存。

建议对常用 Audio 进行缓存，避免用户每次练习都重新调用 TTS。

### AI / LLM

可使用任意稳定的大模型 API。

用途主要是：

-   生成 scenario 变体；
-   caller script；
-   explanation；
-   SEO 辅助。

不要把实时 LLM 调用放在所有核心训练步骤中。

优先：

> **提前生成 + 审核 + 缓存**

从而降低：

-   成本；
-   latency；
-   随机错误。

### Analytics

推荐至少接入：

-   Google Analytics
-   Google Search Console
-   产品事件 Analytics（PostHog 等）

必须追踪：

``` text
Landing Page
→ Start Free Test
→ Finish Free Test
→ View Result
→ Click Unlock
→ Checkout
→ Purchase
```

## 17. CritiCall 官方考试结构调研

> 调研更新时间：2026-08-20

本节依据 CritiCall / Biddle Consulting Group 官方网站、官方考生准备指南、
官方测试模块清单和官方 Applicant FAQ 整理。

### 17.1 核心结论：不存在全国统一固定试卷

CritiCall 不是一张所有考生完全相同的全国统一考试，而是一套由招聘机构自行配置的
**test battery**。

每个 911 / public-safety agency 可以自行决定：

-   使用哪些测试模块；
-   模块出现的顺序；
-   测试在现场还是远程进行；
-   是否使用远程监考；
-   各模块的评分标准和通过标准；
-   测试通过后进入哪一轮招聘流程。

官方说明，系统会按照机构选择的配置让模块依次出现，直到考生完成整场测试，并自动
评分大部分表现。

因此产品和 SEO 内容中不应该声称：

-   CritiCall 固定包含某几个 section；
-   所有考生都会参加完全相同的模块；
-   存在全国统一 passing score；
-   我们的练习等同于真实 CritiCall 试卷。

更准确的表达是：

> Practice for skills commonly measured by agency-configured CritiCall and
> public-safety dispatcher hiring assessments.

### 17.2 考生通常经历的测试流程

#### 1. 招聘机构发出测试邀请

CritiCall 通常是 dispatcher / calltaker 招聘流程中的能力测试环节。机构先完成报名或
初步筛选，再向候选人提供测试时间、地点或在线测试方式。

#### 2. 登录系统并阅读说明

正式测试前通常包括：

-   系统操作说明；
-   耳机和音量检查；
-   鼠标与键盘操作说明；
-   当前模块的作答规则；
-   不计分的 practice items。

官方 Candidate Guide 说明，每个模块开始时通常会提供练习题，练习题不计入最终
成绩，而且考生通常可以选择跳过练习部分。

#### 3. 依次完成机构选择的模块

模块会一个接一个出现。考试可能同时使用：

-   键盘；
-   鼠标；
-   耳机；
-   屏幕中的数据录入字段；
-   限时弹出的 emergency messages。

官方 Applicant FAQ 表示，整套测试通常平均需要约 **1--3 小时**，但实际时长取决于
机构配置的模块数量。

#### 4. 系统自动评分

可能被记录和评分的指标包括：

-   输入正确率；
-   输入速度；
-   是否填入正确字段；
-   反应时间；
-   决策是否符合给定规则；
-   是否遗漏信息；
-   多任务情况下的综合表现。

最终由招聘机构根据自己的标准决定是否通过，不存在统一的官方全国分数线。

### 17.3 官方公布的模块范围

官方 FAQ 表示 CritiCall 软件包含 20 多种测试，但每个机构只会选择适合其岗位的部分。
官方模块清单可按能力分为以下几组。

#### A. 数据输入与键盘操作

##### Computerized Data Entry

-   将听到或看到的信息输入电脑；
-   同时考察速度和准确率；
-   信息必须输入到正确字段。

官方 Candidate Guide 展示的典型字段包括：

-   Last Name
-   First Name
-   Telephone
-   Address
-   City
-   Zip
-   Vehicle Identification Number
-   License Plate
-   Driver's License

##### Keyboarding

-   根据屏幕上的文字输入段落；
-   主要评分指标为 words per minute；
-   同时要求保持准确率。

##### Cross Referencing

-   从列表中查找指定信息；
-   考察字母顺序、字符识别和数字搜索；
-   查找请求可能通过文字或语音提供。

##### Perceptual Ability

-   比较相似的字母和数字序列；
-   排除非常接近、容易混淆的错误项。

#### B. 音频理解和来电摘要

##### Oral Comprehension / Call Summarization 1 & 2

-   听懂语音叙述；
-   通过键盘记录或总结主要事实；
-   过滤无关信息；
-   Call Summarization 2 是更高级的版本。

##### Call Summarization 2 MT

在 Call Summarization 2 中加入必须立即响应的 emergency response items。

##### Call Summarization 2 E911

-   听取并理解可听信息；
-   将信息准确输入电脑；
-   同时执行 decision-making task。

##### Call Summarization 2 MT E911

在 E911 版本基础上增加更多决策和多任务项目，分数综合考虑：

-   数据录入准确率；
-   多任务响应；
-   决策题表现；
-   选择题表现。

#### C. 多任务与快速决策

##### Multi-Tasking / Advanced Decision Making

-   在执行其他任务的同时做出判断；
-   包含 deductive reasoning 和 reaction time；
-   使用有限响应时间模拟 dispatch 环境。

官方 Candidate Guide 给出四类 emergency response 规则：

-   **Police**：有人试图、威胁或已经伤害他人，或正在损害他人财产；
-   **Fire**：出现烟雾、火焰、火警，或有人被困需要救援；
-   **EMS**：出现需要医疗人员介入的紧急医疗状况；
-   **Utility**：公共供水、电力、天然气、路灯、交通信号或下水系统故障。

官方特别要求考生：

> 只使用测试提供的决策规则，不依赖自己对真实警察、消防、EMS 或 agency 流程的
> 既有知识。

Emergency message 的具体规则包括：

-   每条通常只有 **15 秒**响应时间；
-   选错机构不得分；
-   超过 15 秒未作答不得分；
-   消息可能在考生执行另一项任务时突然出现。

#### D. 短期记忆

##### Memory Recall

先显示多组配对信息，几秒后隐藏，再要求根据其中一个元素选择原来的配对内容。

例如：

``` text
Red    → Dodge
Yellow → Ford
Green  → Chevrolet
```

##### Memory Recall: Audio

听取序列号、VIN、车牌或其他字母数字代码，然后从记忆中输入。

##### Memory Recall: Numeric (Audio)

听取不带区号的电话号码，然后从记忆中输入。

#### E. 地图和空间定位

##### Position Locating

-   根据口头或文字提供的方向确定人员位置；
-   使用与工作相关的简单场景。

##### Map Reading / Geographic Directions

-   选择到达目的地的最直接路线；
-   遵守地图中的交通标志和限制；
-   使用左、右、North、East、South、West 等基础方向。

官方 FAQ 表示地图通常只包含基础元素，例如：

-   街道；
-   路口；
-   桥；
-   河流；
-   铁路。

不要求考生具备专业地图训练。

#### F. 阅读、语言和基础认知

##### Reading Comprehension

阅读短文，理解并记住其中的细节。

##### Sentence Clarity

判断哪一种句子或表达方式能够最清晰地陈述事实。

##### Spelling

拼写常见但容易混淆或误用的单词。官方指南举例说明，类似 `patients` 和
`patience` 的错误可能影响紧急信息传递。

##### Proofreading

直接修改文档中的拼写、标点和语法错误。

##### Numerical Ability

处理与工作场景相关的：

-   加法；
-   减法；
-   百分比；
-   距离；
-   时间；
-   金额。

##### Frequency of Information / Probability Determination

-   根据信息判断最可能的解决方案；
-   使用基础概率逻辑；
-   过滤无关信息。

### 17.4 测试操作中的重要细节

根据官方 Candidate Guide，产品设计和训练内容应注意以下真实操作特点：

-   很多语音信息通过耳机播放；
-   考生通常可以调整耳机音量；
-   部分界面只允许输入大写字母；
-   正式题目通常不能遗漏，跳题可能被扣分；
-   部分屏幕需要使用滚动条查看完整内容；
-   选择题使用鼠标单击；
-   数据必须输入到正确字段，而不只是文本内容正确；
-   Tab 和 Shift + Tab 可用于切换数据字段；
-   Emergency response 任务可能打断当前任务；
-   考生不需要 dispatcher 专业知识，但需要遵循系统给定规则。

### 17.5 CritiCall 3D

CritiCall 官方当前推广的新版本称为 **CritiCall 3D**，它把考察范围分为三个维度：

1.  **Operational**：数据输入、记忆、地图、决策、多任务等传统硬技能；
2.  **Behavioral**：可靠性、自信、抗压、任务管理等行为特征；
3.  **Situational**：在接近真实工作情境的 scenario 中判断如何响应。

官方测试清单还列出可以与 TestGenius 集成的资源：

-   Behavioral / Customer Service Situational Judgment Testing；
-   Personality Testing；
-   Remote Proctoring；
-   Language Assessments；
-   Microsoft Office Training。

这些项目不一定都会出现在每个考生的 CritiCall 测试中，其中一些属于机构额外购买或
集成的产品能力。因此 MVP 不应把它们描述为经典 CritiCall 的固定 section。

### 17.6 对当前 Demo 的影响

当前 Demo 已经覆盖：

-   基础 Data Entry；
-   Memory Recall；
-   Audio Data Entry；
-   Pressure Interruption；
-   Police / Fire / EMS 基础决策。

根据官方结构，下一步 Demo 优先级调整为：

#### 第一优先级

1.  Data Entry 增加官方指南中更完整的字段；
2.  Decision Making 增加 Utility；
3.  Emergency message 增加 15 秒倒计时；
4.  在任务前明确展示并训练四条 decision rules；
5.  增加 telephone、plate、VIN 的 Audio Memory；
6.  增加基础 Call Summarization。

#### 第二优先级

-   Cross Referencing；
-   Perceptual Ability；
-   Map Reading；
-   Position Locating；
-   更完整的 Call Summarization + Multitasking。

#### 第三优先级

-   Reading Comprehension；
-   Spelling；
-   Proofreading；
-   Sentence Clarity；
-   Numerical Ability；
-   Probability / Frequency。

MVP 不需要实现所有官方模块，但长期训练引擎应该支持按模块组合成不同的
**dispatcher skills test battery**，而不是假定只有一套固定流程。
