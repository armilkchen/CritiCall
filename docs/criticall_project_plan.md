# CritiCall / 911 Dispatcher Skills Prep 项目方案

## 1. 项目背景

### 1.1 项目起点

本项目来自对"微垂直职业考试知识付费"模式的调研。

目标不是进入 SAT、雅思、CompTIA 等高度拥挤的大型考试市场，而是寻找：

-   搜索流量不必很大，但必须长期存在；
-   用户有明确考试日期和通过目标；
-   考试结果与求职、入职或职业机会相关；
-   用户有真实付费意愿；
-   已有竞争者可以验证市场，但尚未严重饱和；
-   不依赖很强的行业专业知识；
-   可以主要依靠官方公开资料、公开互联网资料、AI 和程序化内容生产；
-   产品不能只是容易被 AI Summary 替代的静态文章或 PDF。

经过对多个美国、加拿大、英国、爱尔兰及欧洲职业考试方向的横向扫描，CritiCall
/ 911 Dispatcher Hiring Test 是目前较符合条件的候选。

### 1.2 为什么选择 CritiCall

CritiCall 常用于 911 Dispatcher / Public Safety Dispatcher / Call Taker
等岗位的招聘测试。

它与传统职业资格考试最大的不同是：

**它主要测试能力，而不是专业知识。**

常见能力包括：

-   Data Entry
-   Audio Data Entry
-   Typing
-   Short-Term Memory
-   Decision Making
-   Multitasking
-   Cross Referencing
-   Map Reading / Geographic Orientation
-   Call Summarization
-   Reading Comprehension
-   Spelling / Proofreading
-   Basic Numerical Ability

不同招聘机构可以选择不同测试模块，因此不存在完全统一的全国试卷。

这意味着本项目不能声称复刻真实 CritiCall，也不能提供所谓"真实考试题"。

产品定位应该是：

> **911 Dispatcher Skills Practice / CritiCall-style Test Preparation**

核心价值不是"告诉用户 CritiCall 考什么"，而是让用户真正练习这些能力。

## 2. 市场判断

### 2.1 用户痛点

目标用户通常处于非常明确的时间窗口：

> "我申请了 dispatcher，现在两周后要参加测试。"

他们的核心问题不是：

> "CritiCall 是什么？"

而是：

> "我到底准备好了吗？"

> "我的 typing 没问题，但 multitasking 会不会挂？"

> "哪里可以练 audio data entry？"

> "付费 practice test 到底值不值得？"

这种用户具有：

-   明确 Deadline；
-   求职驱动；
-   Pass / Fail 心态；
-   考试焦虑；
-   较高的即时购买意图。

### 2.2 已验证的商业市场

当前市场已有多个付费玩家，例如：

-   JobTestPrep
-   JobPrepCentral
-   9-1-1 Professor
-   其他 dispatcher / aptitude test prep 网站

现有产品价格大致覆盖约 \$20 到 \$60+
的区间，并存在长期用户评价和真实购买讨论。

因此本项目不需要重新证明：

> "用户会不会为 CritiCall preparation 付钱？"

答案已经得到市场验证。

我们的任务是判断：

> **能否用更聚焦、更现代、更强交互的产品，在这个已经存在的市场里获得一小部分份额。**

### 2.3 对竞争的态度

本项目不追求"完全没有竞争"。

相反：

**存在竞品通常意味着市场已经被验证。**

真正需要避免的是：

-   大量专业品牌；
-   大量成熟 SaaS；
-   极高 SEO 权重；
-   用户已经形成极强品牌认知；
-   产品严重同质化且价格被压到极低。

CritiCall 当前属于：

> **有成熟玩家，但尚未达到完全人满为患。**

因此适合进行 MVP 验证。

## 3. 核心产品定位

不要把网站定位为：

> "1000+ CritiCall Questions"

也不要主要卖：

> "Ultimate CritiCall PDF Guide"

推荐定位：

# Train for the pressure of a dispatcher hiring test.

核心概念：

> **用户单独做每项能力可能很好，但在中断、多任务和时间压力出现后，准确率会明显下降。**

因此我们的差异化不是题库数量，而是：

## Pressure Training

产品希望回答：

> **What happens to your accuracy under pressure?**

## 5. MVP 产品范围

第一版不要追求覆盖所有 CritiCall 模块。

### 必做模块

#### 1. Typing & Data Entry

测试：

-   打字速度；
-   准确率；
-   Name / Address / Phone / Plate 等结构化数据输入。

#### 2. Alphanumeric / VIN / Plate Practice

程序自动生成：

-   VIN-like strings
-   Plate numbers
-   Unit IDs
-   Phone numbers
-   Mixed alphanumeric sequences

无需传统人工题库。

#### 3. Audio Data Entry

AI/TTS 播放：

-   姓名
-   地址
-   电话
-   Vehicle
-   Plate
-   其他结构化信息

用户听后填写对应字段。

#### 4. Short-Term Memory

示例：

显示：

`K7F29Q`

数秒后隐藏。

要求 Recall。

后续可扩展：

-   Audio memory
-   Address memory
-   Vehicle information memory

#### 5. Decision Making

基于一个经过人工审核的简单规则体系生成 scenario。

例如：

-   Fire-related incident → Fire
-   Medical emergency → EMS
-   Crime / suspicious activity → Police

重点是测试快速分类和规则执行，不模拟真实 911 dispatch protocol。

#### 6. Multitasking / Interruption

这是 MVP 核心。

例如：

用户正在输入：

-   VIN
-   Address
-   Caller information

突然出现：

> Incoming Incident

用户需要：

1.  暂停当前任务；
2.  完成快速判断；
3.  回到原任务；
4.  保持准确率。

系统比较：

-   Baseline Accuracy
-   Pressure Accuracy
-   Pressure Drop

### V1.1 再增加

-   Map Reading
-   Cross Referencing
-   Call Summarization

### 后续再考虑

-   Reading Comprehension
-   Spelling
-   Proofreading
-   Numerical Ability
-   Probability / Information Frequency
-   Agency-specific training

## 6. 内容与"题库"策略

### 6.1 不建立传统庞大题库

本项目不应该人工制作 5,000 道固定题。

大量内容都可以程序生成。

例如：

#### Alphanumeric

``` text
7KX29B
1HGCM82633A004352
82QF7M
```

#### Address

``` text
1842 West Pine Street, Apt 4B
781 North Oak Avenue
2635 East Jefferson Road
```

#### Memory

随机生成字符串、号码、地址和姓名组合。

#### Cross Reference

动态生成大量高度相似的数据：

``` text
AJK274
AJK247
AJX274
AJM274
```

然后要求用户寻找指定目标。

因此营销语言可以从：

> 1,000+ Questions

变成：

> **Unlimited Adaptive Drills**

### 6.2 AI 负责什么

AI 适合：

-   Scenario 文案变体；
-   Caller script；
-   Call summarization 内容；
-   SEO 内容辅助；
-   Explanation；
-   不同难度的语言表达；
-   生成自然的无关信息和干扰信息。

### 6.3 AI 不负责什么

AI 不应该自由决定：

-   官方 passing score；
-   某 agency 的考试结构；
-   真实 CritiCall 内容；
-   关键训练规则的正确答案；
-   Police / Fire / EMS 等分类规则。

关键答案应该由：

> **人工审核的规则集 + 程序逻辑**

决定。

## 7. Audio 技术路线

Audio 是产品的重要组成部分，但不需要人工录制大量语音。

推荐流程：

``` text
Structured Data
      ↓
Script Generator
      ↓
TTS
      ↓
Audio Playback
      ↓
User Input
      ↓
Programmatic Scoring
```

例如系统首先生成：

``` text
Name: Jennifer Collins
Address: 1842 West Pine Street
Phone: 555-827-1946
Vehicle: Blue Honda Civic
Plate: 7KX29B
```

再生成语音脚本：

> Hi, my name is Jennifer Collins. I'm at 1842 West Pine Street. There's
> a blue Honda Civic outside...

通过 TTS 转换为语音。

用户听完填写：

-   Name
-   Address
-   Phone
-   Vehicle
-   Plate

因为系统本身保存结构化标准答案，因此评分不需要 LLM。

### Audio 难度

#### Easy

-   慢速；
-   信息顺序固定；
-   无干扰。

#### Normal

-   正常语速；
-   顺序随机；
-   少量无关信息。

#### Hard

加入：

-   信息纠正；
-   重复；
-   更快语速；
-   更长句子。

例如：

> It's 1842---sorry, 1846 West Pine Street.

#### Pressure

播放 Audio 的同时加入：

-   popup alert；
-   memory task；
-   decision task；
-   interruption。

### TTS 注意事项

数字、车牌、VIN 等不要完全依赖 TTS 自动解释。

程序应先转换为预期读法。

例如：

``` text
7KX29B
```

转换为：

``` text
Seven Kilo X-ray Two Nine Bravo
```

再交给 TTS。

后期可增加：

-   不同声音；
-   不同语速；
-   不同口音；
-   紧张/平静 caller；
-   background noise。

MVP 暂时不需要复杂背景噪音。

## 8. 技术架构建议

目标：

> **快速上线，而不是搭建复杂平台。**

### Frontend

推荐：

-   Next.js
-   React
-   TypeScript
-   Tailwind CSS

原因：

-   SEO 友好；
-   Landing Page 和 Web App 可以共用；
-   很适合 Timer / Keyboard / Audio / Interactive Drill；
-   后续 Programmatic SEO 容易扩展。

### Backend

可以直接使用：

-   Next.js API Routes / Server Actions

早期无需单独建设复杂后端。

### Database

推荐：

-   PostgreSQL
-   Supabase 或 Neon

核心数据：

-   User
-   Session
-   Drill Result
-   Assessment
-   Purchase
-   Training History
-   Scenario Template

### Authentication

可使用：

-   Clerk
-   Supabase Auth
-   Auth.js

免费 Assessment 尽量不要强制登录。

付款后再创建账户。

### Payment

推荐：

-   Stripe

MVP：

> 一次性付款 → 30 天访问权限

暂时不需要 Subscription。

### TTS

可根据成本和效果选择主流 TTS API。

MVP 核心要求：

-   英文自然；
-   latency 可接受；
-   数字/字母读音稳定；
-   支持预生成或缓存。

建议对常用 Audio 进行缓存，避免用户每次练习都重新调用 TTS。

### AI / LLM

可使用任意稳定的大模型 API。

用途主要是：

-   生成 scenario 变体；
-   caller script；
-   explanation；
-   SEO 辅助。

不要把实时 LLM 调用放在所有核心训练步骤中。

优先：

> **提前生成 + 审核 + 缓存**

从而降低：

-   成本；
-   latency；
-   随机错误。

### Analytics

推荐至少接入：

-   Google Analytics
-   Google Search Console
-   产品事件 Analytics（PostHog 等）

必须追踪：

``` text
Landing Page
→ Start Free Test
→ Finish Free Test
→ View Result
→ Click Unlock
→ Checkout
→ Purchase
```

## 10. 与 AI Summary 的关系

静态内容：

> What is CritiCall?

未来非常容易被 Google AI Overview、ChatGPT 等摘要。

因此本项目不能依赖纯信息 SEO。

真正抗 AI 的资产是：

-   Interactive Practice
-   Audio
-   Timer
-   Memory
-   Multitasking
-   Simulation
-   Scoring
-   Progress Tracking

AI 可以告诉用户：

> "如何练 multitasking。"

但不能替用户完成：

> **20 分钟 Multitasking Training。**

因此 SEO 的作用是：

> **获客**

而产品工具的作用是：

> **留住用户 + 转化。**

## 15. 项目原则

### 原则 1：不要过度开发

目标不是第一版超过 JobTestPrep。

目标是：

> **用最小产品证明用户愿意从 Google 进入 → 玩免费测试 → 付款。**

### 原则 2：不要追求题库数量

核心资产：

> **Training Engine**

而不是：

> Question Database。

### 原则 3：程序生成优先

能够通过：

-   Template
-   Rules
-   Random Generation
-   TTS

解决的问题，不人工制作大量固定内容。

### 原则 4：AI 是生产工具，不是产品噱头

用户购买的不是：

> AI CritiCall Coach

而是：

> **更有效的训练。**

### 原则 5：核心差异化围绕 Pressure

长期品牌定位：

> **Don't just practice the questions. Train to stay accurate under
> pressure.**

## 16. 当前项目结论

当前建议：

但定位不是传统考试题库网站。

> **一个面向 911 Dispatcher Applicants 的技能训练与压力模拟工具。**

Pressure Training 和 Full Simulation 负责形成付费价值。

第一版不追求：

-   大而全；
-   1000+ 人工题库；
-   完整复刻 CritiCall；
-   复杂 AI Agent；
-   所有 agency；
-   移动 App。

> **Search → Practice → Realize Weakness → Pay → Train**

如果这一闭环成立，再扩展更多 dispatcher hiring tests
